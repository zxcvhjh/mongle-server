## 🔥 Technical Issues & Problem Solving

단순한 기능 구현을 넘어, 서비스 운영 시 발생할 수 있는 DB 부하 및 동시성 문제를 사전에 고민하고 해결했습니다.

### 1. Redis Write-Back 패턴을 통한 DB 쓰기 부하 최적화
* **문제 상황**: 좋아요/싫어요 등 빈번하게 발생하는 리액션 데이터를 매번 RDB에 직접 반영할 경우 심각한 쓰기 부하가 예상됨.
* **해결 방법**: 
  * 리액션 데이터를 Redis에 임시 저장하고, Spring Scheduler를 통해 RDB에 일괄 동기화(Write-Back) 처리.
  * 동시성 이슈를 원천 차단하기 위해 **Lua 스크립트**를 작성하여 원자적 연산 보장.
  * 다중 서버 환경에서 스케줄러가 중복 실행되는 것을 막기 위해 **ShedLock 기반 분산 락** 적용.
* **결과**: 100번의 쓰기 요청을 1번의 쿼리로 압축하여 DB 부하를 획기적으로 감소시킴. 또한 Redis의 AOF 옵션을 설정하여 서버 다운 시 데이터 유실을 방어함.

### 2. Redis 캐싱을 통한 대량 읽기 요청 성능 개선 및 방어 전략
* **문제 상황**: 지도 탐색 시 대규모 게시물 조회 이력이 발생하여 읽기 부하가 가중됨. 캐시 적용 시 발생할 수 있는 보안적/구조적 취약점 대비 필요.
* **해결 방법 및 성과**:
  * 읽기 부하 감소를 위해 조회 이력을 Redis로 처리.
  * **Cache Stampede 방어**: 캐시 초기화 시 발생하는 RDB 순간 부하를 막기 위해 Cache Warming과 분산 락 결합.
  * **캐시 펜딩/관통 공격 방어**: 존재하지 않는 데이터에 대한 공격을 막기 위해 빈 데이터를 캐싱(10분 TTL) 처리.
  * **메모리 최적화**: 게시물 생명주기 특성에 맞춰 24시간 TTL을 설정해 효율적인 메모리 라이프사이클 관리.

### 3. DB 성능 및 응답 속도 최적화
* **Redis Pipeline 적용**: 다건의 명령어를 한 번에 전송하여 네트워크 왕복 비용(RTT) 대폭 절감.
* **N+1 문제 해결**: JPA `@EntityGraph`를 적극 활용하여 불필요한 연관관계 쿼리 호출 방어.
* **결정론적 페이지네이션**: 데이터 삽입/삭제가 빈번한 커뮤니티 특성을 고려해, QueryDSL 기반의 커서(Cursor) 페이지네이션을 구현하여 일관된 조회 성능 확보.
